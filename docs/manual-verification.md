## Подготовка релиза 1.0.0

Универсальная Release-сборка завершилась с exit 0: `/private/tmp/matasehat-v1-universal-release.log`. Проверены версия 1.0.0, build 1, LSMinimumSystemVersion=26.5, LSUIElement=true и наличие архитектур arm64 и x86_64. Подпись ad-hoc проходит `codesign --verify --deep --strict` до упаковки и после извлечения ZIP; исполняемый файл после извлечения совпадает с исходным по SHA-256. Архив и контрольная сумма подготовлены в `build/releases/v1.0.0/` вне Git. Подпись Developer ID и notarization отсутствуют.

## Неподтверждённые сценарии

Полноэкранное стороннее приложение, смена Spaces, печать/прокрутка в другом приложении во время эффекта, реальный сон и блокировка/разблокировка, реальная регистрация/разрегистрация автозапуска, VoiceOver и системные Reduce Motion/Reduce Transparency/Increase Contrast остаются ручными проверками. Попытка подготовить отдельное текстовое окно через автоматизацию зависла; результат не засчитывается как проверка этих сценариев. Реальные сон/блокировка и регистрация требуют отдельной сессии проверки, чтобы не прерывать работу пользователя.

Для fullscreen/Spaces используются публичные AppKit window flags. Сигналы loginwindow screenIsLocked/screenIsUnlocked из DistributedNotificationCenter изолированы в SystemActivityMonitor; их строковые имена не являются документированным контрактом Apple. Unit-тест причин остановки не доказывает доставку реальных системных уведомлений.

## Решения при реализации

- Встроенное создание worktree вернуло «Not a git repository», хотя локальный Git работает. Реализация остаётся в исходном каталоге на ветке `feature/native-blink-reminders`; файлы доступны открытому Xcode, поэтому параллельные ручные изменения требуют внимания.
- План не содержал шагов коммита; после реализации изменения сначала оставили для просмотра. Следующим сообщением пользователь явно запросил коммит, объединение в `master` и отправку в `Samaan98/MataSehat`; это отдельный этап интеграции.
- Добавлен набор причин остановки вместо одного флага: сон, дисплей, неактивная сессия и блокировка могут перекрываться. Поддержка реальных уведомлений нуждается в перечисленных выше ручных проверках.
- Нативная сцена SwiftUI Settings зарегистрирована через публичный NSHostingSceneRepresentation из SDK 26 в applicationWillFinishLaunching. Это позволяет открыть её из жизненного цикла до первого нажатия значка. Кнопка панели использует environment.openSettings именно этой сцены через делегат, затем окно переиспользуется; ниже macOS 26.5 приложение не поддерживается.
