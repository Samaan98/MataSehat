# Проверка MataSehat — 5 октября 2026

Окружение: macOS 26.5.2 (25F84), MacBook Pro arm64, Xcode 26.5, Swift 6.3.2. Минимальная версия приложения и тестов — macOS 26.5.

## Дополнение: доступность переключателя запуска при входе

Исправлено преждевременное отключение переключателя при `SMAppService.Status.notFound`. Этот статус теперь отображается как выключенный автозапуск и позволяет пользователю попробовать регистрацию. Статусы включённого автозапуска и необходимости системного разрешения сохранены; результат регистрации по-прежнему определяется macOS, ошибки показывает контроллер.

Регрессионный тест сначала воспроизвёл ошибку: `notFound` возвращал `unavailable` вместо `disabled`. После исправления тихий прогон завершился с exit 0: 40 тестов, 52 запуска с учётом параметров, 0 ошибок и пропусков. Отчёт: `/private/tmp/matasehat-login-green.xcresult`; лог: `/private/tmp/matasehat-login-green.log`. Проверены все четыре известных системных статуса и существующая обработка ошибок регистрации/системного разрешения. UI-тесты и `OverlayWindowTests` исключены; реальные окна не открывались и системная регистрация автозапуска не изменялась.

Release-сборка завершилась с exit 0: `/private/tmp/matasehat-login-release.log`. Приложение собрано в `/private/tmp/matasehat-native-dd/Build/Products/Release/MataSehat.app`. Уже запущенная пользовательская копия не останавливалась и не заменялась; для применения исправления её нужно пересобрать и перезапустить либо перейти на новую сборку. Компилятор не выдал предупреждений; служебное предупреждение AppIntents сообщает об отсутствии зависимости от этого framework.

## Дополнение: отдых 20–20–20 и интервал 5 секунд

Полный прогон финального кода перед коммитом завершился с exit 0: 47 тестов, 56 запусков с учётом параметризованных сценариев, 0 ошибок и пропусков. Отчёт: `/private/tmp/matasehat-commit-breaks-tests.xcresult`; лог: `/private/tmp/matasehat-commit-breaks-tests.log`. Предупреждений компилятора нет. После финальной правки оформления кнопки также отдельно прошли все 4 затронутые проверки окна и обеих тем: `/private/tmp/matasehat-break-card-tests.xcresult`. Последние снимки просмотрены; основная кнопка читаема и в неактивном окне.

Окончательная Release-сборка завершилась с exit 0 без предупреждений компилятора: `/private/tmp/matasehat-break-final-release.log`. Приложение обновлено в `build/MataSehat.app`; проверка ad-hoc подписи прошла, LSMinimumSystemVersion=26.5 и LSUIElement=true. Эта копия запущена с открытием настроек: через accessibility проверены новый вариант 5 секунд, переключатель автоматического отдыха и кнопка показа приглашения. Пользовательские параметры морганий сохранены.

Swift Testing проверяет приглашение через 1 200 секунд, ручное начало 20-секундного отдыха, откладывание на 300 секунд, раннее завершение, отключение автоматических приглашений, сохранение общей паузы, возврат после сна, скачки настенных часов и интервал морганий 5 секунд. Изменение параметров моргания не сдвигает следующий отдых. Старые настройки получают включённые автоматические приглашения по умолчанию, повреждённый флаг безопасно восстанавливается.

XCTest запускает настоящую карточку: откладывает приглашение, начинает отдых вручную, проверяет уменьшение видимого отсчёта и автоматическое закрытие после 20 секунд. После перезапуска проверяет сохранённые 5 секунд и выключенную автоматику, затем начинает отдых из строки меню и завершает его раньше. Unit-тест окна проверяет отсутствие автоматического изменения keyWindow, доступность нажатий и переиспользование единственного NSPanel.

Независимое ревью выявило важный дефект: переключатель автоматических приглашений отменял уже начатый отдых. Регрессия воспроизведена тестами для обоих направлений переключения; исправление сохраняет текущий срок и применяет настройку к следующим приглашениям. Дополнительно данные accessibility подтвердили зависший видимый отсчёт на 20 секундах; после передачи меняющегося числа в дочерний View отсчёт уменьшается, что проверяет UI-тест.

Реальный 20-минутный цикл и карточка поверх полноэкранного стороннего приложения не проверялись вручную: долгие интервалы проверены управляемыми часами, реальный таймер — 20-секундным UI-сценарием. Ограничения платформенных проверок ниже сохраняются.

## Автоматическая проверка

Заключительная полная сборка и тесты: 29 тестов, 37 запусков с учётом параметризованных сценариев, 0 ошибок, 0 пропусков. Отчёт: `/private/tmp/matasehat-ready-tests.xcresult`; лог: `/private/tmp/matasehat-ready-tests.log`. Предупреждений компилятора нет. Xcode пишет служебное сообщение DebuggerVersionStore, которое не влияет на прохождение тестов.

Проверены расписание на монотонных часах, сроки пауз по Date, замена и восстановление пауз, возврат после сна, отсутствие очереди пропущенных сигналов, предпросмотр на паузе, игнорирование устаревшего завершения, сохранение параметров всех эффектов, повреждённые поля, огромный конечный timestamp, отмена/повторный start контроллера, ошибки и системное разрешение автозапуска, перекрытие причин сна/блокировки, свойства неактивирующего окна.

UI-тесты действительно запускают приложение и проверяют автоматическое открытие настроек без нажатия значка строки меню, три режима, sliders заметности/длительности, предпросмотр, ручную паузу, продолжение и сохранение после перезапуска. Отдельный сценарий закрывает настройки, открывает панель строки меню и возвращает единственное окно настроек, затем повторяет открытие без создания дубликата. Тестовые suites отделены от пользовательских настроек, включая неверное имя suite. Снимки обеих тем сняты с явно активированным тестовым приложением и просмотрены.

Ревью независимым агентом выявило один важный дефект: повреждённый очень большой срок паузы приводил к переполнению Int при отображении. Исправление проверено тестом, который действительно падает после временного удаления проверки диапазона и проходит после её восстановления. Остальных важных замечаний и отложенных мелких замечаний нет. Дополнительный UI-сценарий обнаружил неправильный контекст openSettings в MenuBarExtra. Кнопка теперь вызывает публичный environment.openSettings зарегистрированной сцены через делегат и dismiss панели; повторное открытие проверено отдельным прошедшим UI-тестом.

## Неподтверждённые сценарии

Полноэкранное стороннее приложение, смена Spaces, печать/прокрутка в другом приложении во время эффекта, реальный сон и блокировка/разблокировка, реальная регистрация/разрегистрация автозапуска, VoiceOver и системные Reduce Motion/Reduce Transparency/Increase Contrast остаются ручными проверками. Попытка подготовить отдельное текстовое окно через автоматизацию зависла; результат не засчитывается как проверка этих сценариев. Реальные сон/блокировка и регистрация требуют отдельной сессии проверки, чтобы не прерывать работу пользователя.

Для fullscreen/Spaces используются публичные AppKit window flags. Сигналы loginwindow screenIsLocked/screenIsUnlocked из DistributedNotificationCenter изолированы в SystemActivityMonitor; их строковые имена не являются документированным контрактом Apple. Unit-тест причин остановки не доказывает доставку реальных системных уведомлений.

## Решения при реализации

- Встроенное создание worktree вернуло «Not a git repository», хотя локальный Git работает. Реализация остаётся в исходном каталоге на ветке `feature/native-blink-reminders`; файлы доступны открытому Xcode, поэтому параллельные ручные изменения требуют внимания.
- План не содержал шагов коммита; после реализации изменения сначала оставили для просмотра. Следующим сообщением пользователь явно запросил коммит, объединение в `master` и отправку в `Samaan98/MataSehat`; это отдельный этап интеграции.
- Добавлен набор причин остановки вместо одного флага: сон, дисплей, неактивная сессия и блокировка могут перекрываться. Поддержка реальных уведомлений нуждается в перечисленных выше ручных проверках.
- Нативная сцена SwiftUI Settings зарегистрирована через публичный NSHostingSceneRepresentation из SDK 26 в applicationWillFinishLaunching. Это позволяет открыть её из жизненного цикла до первого нажатия значка. Кнопка панели использует environment.openSettings именно этой сцены через делегат, затем окно переиспользуется; ниже macOS 26.5 приложение не поддерживается.
